Test notes and technical details

The long version of the support table: for each feature, what was tested, on which discs and drives, and what has only run in the drive simulator so far. The same notes are in the project's README.

What works, and how it was tested

PHYSICAL = real discs in a real drive · VIRTUAL = the drive simulator in the test suite

Burn a data disc from files and folders

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • ISO 9660 + Joliet + UDF bridge; UDF 1.02 by default, 1.50 to 2.60 on request (--udf-rev).
  • With the Windows writer (the default) on real discs on one drive (LG GP60NB50), every file read back identical: a CD-RW, a DVD+RW, a DVD-R and a DVD+R (two sessions each on the DVD-R and DVD+R), and a dual-layer DVD+R holding 5.5 GB across both layers (Windows puts the layer break at half the data).
  • A DVD-RW (Ritek) too, with one difference: Windows' writer formats a blank DVD-RW for overwriting before it writes, so it is never left open for more sessions (the burn says so when that was asked for); every file identical, also after writing it over past the part formatted first.
  • On a second drive (Lite-On iHAS124), a data CD-R (206 MB, 497 files) read back identical

Burn an existing .iso

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

No further notes.

Create .iso image files

PHYSICAL [ PASS ] · VIRTUAL [ N/A ]

Validated against an independent reader (DiscUtils) in the test suite

Verify after burning

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • Reads every sector back and compares it with the image.
  • The drive is told to read the disc itself, not its memory, where burn data can still be held; --strict-verify does that for every read.
  • Damage is reported by file

Hash lists on data discs (SHA256SUMS / BLAKE3SUMS)

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

Optional (--sha256sums, --blake3sums, or checkboxes on the Data Disc screen); written to the disc root and checked file by file after the burn

Rip a data disc to .iso or .bin + .cue

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

No further notes.

Burn an audio CD (Disc-at-Once / Track-at-Once)

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • From WAV, FLAC (built-in decoder, incl. 24-bit / hi-res / surround), MP3/M4A via Media Foundation; .cue sheets (per-track or single-file albums) and .m3u/.m3u8/.pls playlists; loudness leveling or an optional -18 LUFS normalisation with a -1 dBTP limiter, crossfade, preview, printable jewel-case insert.
  • Opus, Ogg and MP3 can also be decoded through the optional ffmpeg download, trimmed to the exact length for gapless albums; that FFmpeg decoding and the -18 LUFS normalisation have only been tested on files and the virtual drive, with one 2021 ffmpeg build, not on a burned disc

Burn, verify or convert Nero, Alcohol 120%, CloneCD and DiscJuggler images

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • .nrg, .mdf/.mds, .ccd/.img, including Mode 2 / XA discs; streamed, no size limit.
  • DiscJuggler .cdi (v2, v3, v3.5) is read as well, checked only on hand-built files that follow the published layout, not on an image made by DiscJuggler; the first data track is used

Copy a disc (one or two drives, several copies)

PHYSICAL [ PARTIAL ] · VIRTUAL [ PASS ]

  • Swap prompts between copies; audio CDs copied track by track.
  • A mixed-mode CD (data track first, then audio) is copied whole with direct drive commands turned on, otherwise only its audio; done on one real drive (LG GP60NB50, copying a CD-RW to a CD-R and a CD-R to a CD-R).
  • An Enhanced CD (audio session, then a data session) is copied whole with direct drive commands on; that copy has run only in the built-in drive simulator.
  • The source audio is read with error checks and re-reads, and a copy stops before writing when sectors still read wrong; real-drive reports welcome

Rip an audio CD to WAV, FLAC, MP3, Opus or AAC + .cue

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • Reads the real TOC and CD-Text; optional MusicBrainz track names, release year and front cover (Cover Art Archive).
  • When MusicBrainz lists editions that name tracks differently, the rip stops before reading the disc and asks which edition you have.
  • Files can go straight into a library folder (Artist\Album (Year)\NN - Title by default, or your own naming template), in several formats from one rip, with folder.jpg and a .cue per album; MP3 can be constant bitrate or VBR (V0-V9).
  • convert-audio (and the app's Convert Audio tab) converts files already on disk, keeping their tags and cover.
  • AAC uses the encoder built into Windows; FLAC, MP3 and Opus use the optional ffmpeg download (no encoder is bundled).
  • Ripping has run on a real drive (LG GP60NB50): tracks from CD-Rs and a CD-RW burned by IgnisDisc came back identical to the source audio.
  • Gap detection (INDEX 00 marks in the .cue, hidden audio before track 1, pre-emphasis) has been tested on the virtual drive only, not on a real disc with such gaps.
  • The encoders and output formats are otherwise tested on the virtual drive only; the built-in FLAC decoder (used for burning) is also checked against files made by the official flac 1.5.0 encoder

AccurateRip verification and read-offset correction

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • Detects your drive's offset from a disc in the AccurateRip database; optional opt-in CUETools Database (CTDB) track and disc CRC-32 lookup (--verify-ctdb, off by default) that also repairs a rip from CTDB parity and keeps the fix only when AccurateRip then matches.
  • On a real CD the CTDB check matched the database and its repair data matched IgnisDisc's own calculation; the repair has fixed a real rip with damage added afterwards (zeroed sectors, flipped samples) against the live database, confirmed by AccurateRip, but has not yet met a physically scratched disc

Secure audio ripping (C2 error pointers and re-reads)

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

Flags suspect sectors; can be slow on badly scratched discs

Archive Studio: span folders across discs

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • SHA-256 manifest on every disc; optional PAR2 recovery data (needs par2.exe) fills the space left on each disc, split over an inner, middle and outer zone with a copy of the volume descriptor in each; recover copies the files off a damaged archive disc and rebuilds them, also with sector 16, the first UDF anchor and one whole zone destroyed (tested on images).
  • An archive burn can also write a HEALTH.json and HEALTH.svg report, and check-disc --compare sets a later read against it; this has only been tested on the virtual drive, not run on a real drive

Quick or full erase of rewritable media

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

No further notes.

Re-burn a used DVD+RW / DVD-RAM

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

Asks before replacing the files on the disc (--overwrite on the command line); finalized CD-RW / sequential DVD-RW require erase first; a DVD-RW written by Windows' writer is in overwrite mode and is written over like a DVD+RW

Surface scan

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

Per-track Full TOC (0x02) scan skips unrecorded multi-session gaps and auto-selects 2352B raw mode on audio tracks

Append a session (multi-session)

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

  • Open and appended sessions omit UDF 1.02 so Windows mounts Joliet across all sessions; names longer than 64 characters are shortened there, and the burn result says so.
  • With the Windows writer on real discs: a DVD-R and a DVD+R, two sessions each, every file of both sessions identical; the DVD+R showed the new session at once, the DVD-R only after the disc was put back in

Bootable discs (El Torito BIOS + UEFI)

PHYSICAL [ PASS ] · VIRTUAL [ PASS ]

Hybrid BIOS + UEFI Boot Catalog verified via physical burn, readback, and rip; boot behaviour depends on your loaders

DVD-Video authoring

PHYSICAL [ PARTIAL ] · VIRTUAL [ PASS ]

  • Requires ffmpeg.exe (the 1-click download).
  • Long movies are compressed to fit: before converting, the DVD-Video screen reads each movie's running time and says whether they fit a 4.7 GB DVD at full quality, compressed (with the video bitrate and how it will look), only on a dual-layer DVD, or on no DVD at all (Burn is then off).
  • When a 4.7 GB DVD would have to compress and a dual-layer DVD would keep a clearly higher bitrate, it offers both (for example 3,587 kbps or full quality for a 2 h 20 min film), and a burn is refused before converting when the disc in the drive is too small.
  • Each film becomes a title with a chapter every 5 minutes, English subtitles from an .srt beside it (or generated with the optional subtitle tool; the DVD-Video screen shows each movie's subtitle source with Choose .srt... and No subtitles), and a title menu with a still from each film and Play / Play with subtitles buttons.
  • The navigation tables follow libdvdread's structures and were checked with libdvdnav (mpv, VLC).
  • Played on one stand-alone player so far, an Xbox Series X: a film with menu, chapters and subtitles on a DVD+RW, and two films on a dual-layer DVD+R played across the layer change.
  • Discs authored before 2026-11-14 did not play there.
  • The authoring options (autoplay, action after a film, chapter interval, subtitles, video quality, title menu) have been checked in the test suite only; no disc made with a non-default choice has been burned or played yet

Generate subtitles for DVD-Video (speech recognition)

PHYSICAL [ PARTIAL ] · VIRTUAL [ N/A ]

  • Optional 1-click download, nothing bundled: whisper.cpp 1.9.5 and its models, every file pinned by SHA-256 (install-subtitle-tool, or the button on the DVD-Video screen).
  • On a PC with an NVIDIA GPU and driver 551.61 or newer it gets the CUDA build and the large-v3-turbo model (2.3 GB download).
  • With an AMD or Intel GPU instead, integrated graphics included, it gets a Vulkan build of the same whisper.cpp source and the large-v3-turbo model (1.6 GB download): whisper.cpp publishes no Windows GPU build for these, so IgnisDisc's own GitHub workflow builds it, with a build provenance attestation.
  • Any other PC gets the processor build and the smaller base model (160 MB).
  • Measured on one PC, on an 86-minute animated feature with English dialogue, against its human-made subtitles: on an RTX 3090, 3.3 min from movie file to .srt (26 times real time) with a word error rate of 24.9%; processor build only (16-core desktop processor, base model), 3.4 min and 34.3%.
  • Through the Vulkan build, speech recognition alone (from the extracted audio) took 18.1 min on Intel UHD Graphics 770 integrated graphics (26.0%), and 60 s on the RTX 3090 (26.1%; the CUDA build took 56 s on the same audio).
  • The Vulkan build has not been run on an AMD GPU yet.
  • The large model on that processor ran at 1.7 times real time (178 s for 5 minutes, about 50 minutes for this film), so the better model needs a GPU.
  • The error rate counts wording the human subtitles shorten too; an invented place name was never heard right.
  • The subtitles are machine-generated: check them before relying on them.
  • burn-dvd --generate-subtitles ("Generate subtitles" on the DVD-Video screen) makes them for movies with no .srt beside them and puts them on the disc as its subtitle track.
  • Authored end to end on the test PC from a 5-minute excerpt: the generated lines appear as the DVD subtitle track and on the menu's "Play with subtitles" button.
  • A full-length film with generated subtitles was burned to a worn DVD+RW on one drive (LG GP60NB50, 2026-11-14), but the read-back check of that disc failed, so it is not counted as a good burn; no disc with generated subtitles has been played in a stand-alone player yet.
  • Muxing the subtitle track needs a recent FFmpeg (the 1-click download): a 2021 build crashed on it

Blu-ray (BD-R / BD-RE)

PHYSICAL [ N/A ] · VIRTUAL [ N/A ]

Not yet: Blu-ray discs are recognised (type, size, layers) and archive sets can be planned for them, and the experimental direct writer handles BD-R and BD-RE of every layer count (single layer, dual layer 50 GB, BDXL 100 and 128 GB) in the drive simulator only, but burning one has never been tried on a real drive

Burn with direct drive commands (experimental)

PHYSICAL [ PARTIAL ] · VIRTUAL [ PASS ]

  • Audio CDs Session-at-Once and data/video discs without the Windows writer (--native on the command line, or "Direct drive commands" in the app — on by default in the app for audio CDs, falling back to the Windows writer if the drive does not offer Session-at-Once, for dual-layer DVD-Video, and for a DVD-RW, in the app and with burn-data and burn-iso, where a quick-erased disc that cannot be left open still goes to the Windows writer (a Settings switch, or --windows-writer on the command line, turns the DVD-RW default off); off by default elsewhere); the disc is always read back and compared.
  • Audio and DVD burns have run on one drive so far (LG GP60NB50) on CD-R, CD-RW, DVD-R, DVD-RW, DVD+R, DVD+RW and dual-layer DVD+R; a second drive (Lite-On iHAS124) has written one data CD-R this way (206 MB, 497 files, every file identical), and no DVD or audio disc.
  • Mixed-mode CDs (a Mode 1 data track, then audio) from a .cue file too: a CD-RW, where Windows read the data track's files back identical, and a CD-R with the write-offset correction on (2,001 data sectors, then 78 minutes of audio, 2026-11-21): the table of contents, CD-Text, data track and every audio sample read back identical after a careful re-read of two sectors, and all 154 files hashed identical through Windows.
  • A Mode 2 / CD-ROM XA data track (MODE2/2352 or MODE2/2336) as track 1 has run only in the drive simulator, not on a real disc.
  • Blank single-layer DVD-R, DVD-RW and DVD+R can also be written this way.
  • A further session on a CD-R, CD-RW, DVD-R, DVD-RW or DVD+R left open is added the same way: on real discs on the same drive, three sessions each on a CD-RW, a CD-R and a DVD+R and four on a DVD-R, every file of every session identical (the first DVD-R try was refused with nothing written, because the drive rejects the writer's old track query on DVD; fixed before these runs); on a DVD-RW too, which must be fully erased before it can be left open: a second session added and the disc closed, every file of both sessions identical (Windows showed the new session after the disc was put back in).
  • On real hardware so far two DVD-Rs on the same drive (Verbatim): one closed in one pass (372 MB), one left open, after which Windows' own writer added a second session; every file of each session identical when read through Windows.
  • Two DVD+RWs too (Verbatim, 372 MB each, every file identical): a used one written over with leave to replace its data, and a new one, formatted first by the drive.
  • A single-layer DVD+R too (Verbatim, 198 MB, finalized by the drive, every file identical).
  • A DVD-RW too (Ritek): closed in one pass after a quick erase (63 MB; the drive took 6 minutes to close it), left open after a full erase (200 MB), and in overwrite mode written over past its formatted part, which the writer expanded first (230 MB); every file identical each time.
  • A DVD-Video disc was written to a used DVD+RW this way too (a 60 s test card, 44 MB): every sector read back and the title decodes in full, this test card was not played in a stand-alone player (a later film disc was; see DVD-Video authoring).
  • A dual-layer DVD+R too (Verbatim, the Ubuntu 26.04 image, 6.5 GB, with the layer break moved to where it was asked for; the drive reported it there and the disc's SHA-256 equalled the image).
  • A two-film DVD-9 (103 and 86 minutes) went onto a dual-layer DVD+R the same way, with the layer break on the cell where the second film starts: every sector read back, the drive reported the break there, and an Xbox Series X played through the first film into the second across the layer change without a stop.
  • Dual-layer DVD-R (layer jump recording, on drives that offer it), DVD-RAM (a real-disc test will not be done: the medium is out of production), BD-R and BD-RE of every layer count (single layer, dual layer 50 GB, BDXL 100 and 128 GB), leaving an audio CD open for a second data session (CD-Extra), that session's optional Blue Book layout (off by default: CD-ROM XA Mode 2 Form 1 with CDPLUS/INFO.CDP and PICTURES), and the optional Audio CD PAR2 recovery session (--recovery-session / rip-audio --repair) have run only in the built-in drive simulator, not on a real disc.
  • Dual-layer DVD-R on a drive without layer jump recording still uses the Windows writer

CD-Text / ISRC on burned audio CDs

PHYSICAL [ PARTIAL ] · VIRTUAL [ PASS ]

  • The Windows writer cannot write lead-in CD-Text.
  • The direct writer (on by default on the Audio CD screen when the drive offers Session-at-Once, or --native on burn-audio) writes CD-Text, ISRC and catalog codes, then reads the disc back and compares it.
  • Run on real hardware on one drive so far (LG GP60NB50): a CD-RW and a CD-R, where CD-Text, ISRC and catalog codes and the audio all read back correctly; not yet checked in a stand-alone CD player

DVD+R book type (bitsetting)

PHYSICAL [ N/A ] · VIRTUAL [ PASS ]

  • An opt-in setting (book-type --get/--set, --book-type, and a checkbox on the burn screens) that sends vendor commands only to drives on a built-in allow-list and otherwise reports "not supported".
  • Run only in the drive simulator so far; never tried on a real DVD+R

Test write (simulation)

PHYSICAL [ PARTIAL ] · VIRTUAL [ PASS ]

  • With the experimental direct writer (--native --test-write): the whole burn with the laser off.
  • Run on one drive (LG GP60NB50) on CD-R and CD-RW.
  • DVD-R has passed a test write on the same drive (a Verbatim DVD-R, still blank after a reload); DVD-RW only in the drive simulator so far; DVD+R discs have none.
  • The Windows writer has no test write

Technical details

CdBurner.Core

  • IsoUdfImageBuilder: ISO 9660, Joliet UCS-2BE, OSTA UDF 1.02 to 2.60 (metadata partition and mirror from 2.50), El Torito BIOS/UEFI boot catalogs; byte-identical output with a fixed build time.
  • DvdVideoAuthoringService, DvdIfoGenerator, DvdNavPackWriter, and DvdStillMenu: VMG/VTS navigation tables, still-frame title menus (Play / Play with subtitles), 5-minute chapters, DvdSubtitleWriter (.srt or SubtitleGenerationService via optional whisper.cpp 1.9.5), and DvdCellLayerBreak for dual-layer DVD-9 discs.
  • Streaming LegacyDiscImageConverter for .nrg, .mdf/.mds, and .ccd/.img (incl. Mode 2 / XA 2336B/2448B sectors), and DiscJuggler .cdi (v2, v3, v3.5; tested on hand-built files only).
  • RedBookPcmConverter (polyphase resampler, TPDF dither, BS.1770-4 -18 LUFS gated loudness with -1 dBTP 4x-oversampled limiter, gapless FFmpeg decoding for .opus/.ogg/.mp3), built-in FlacFileCodec, CD picture tracks (.cue pipeline, simulator-tested), and ArchiveSpanPlanner with 3-zone PAR2 recovery and SHA-256 / BLAKE3 manifests.

CdBurner.Hardware

  • Background ApartmentState.MTA worker (MtaBurnWorker) driving IDiscFormat2Data, IDiscFormat2TrackAtOnce, IDiscFormat2RawCD, and IDiscFormat2Erase.
  • PhysicalSectorReader + Win32ScsiTransport (IOCTL_SCSI_PASS_THROUGH_DIRECT, Full TOC 0x02, READ CD with C2 pointers, READ (10) with FUA for the check after a burn).
  • In-memory virtual drives for tests (VirtualDiscBackend, VirtualMmcDrive) and a compatibility test matrix of 32 simulated drive and media combinations.

CdBurner.Cli, App & Lithography

  • IgnisDisc.exe: WPF desktop studio with 10 dedicated workspaces (including Calibration and Disc Art), OS-synced Dark/Light theme (ThemeManager), per-movie DVD subtitle controls, burn-finished notice (sound + taskbar flash), instant-save settings, eject-after-burn on by default, and pinned-SHA-256 1-click downloads for optional ffmpeg, par2cmdline-turbo 1.5.0, and whisper.cpp 1.9.5.
  • ignisdisc-cli.exe: 40 commands (including rosetta and disc-art) with --json output; it refuses to replace the contents of a rewritable disc unless --overwrite is given.
  • CdBurner.Lithography: headless picture-disc encoding, Rosetta hybrid disc builder, and per-disc calibration fitting.
  • Per-user installer (CdBurner.SetupBootstrapper net48 bootstrapper, no administrator rights) with a small separate Uninstall-IgnisDisc.exe.

Direct drive commands (experimental)

  • Audio CDs: Session-at-Once with SEND CUE SHEET and WRITE (10): CD-Text in the lead-in (R-W sub-channel), ISRC and catalog codes, pre-emphasis and copy bits, INDEX 00 gaps, and audio in front of track 1.
  • Data discs: CD Track-at-Once; DVD-R and DVD-RW Disc-At-Once, or in packets when left open; DVD+R written in sequence and finalized; DVD+RW written over from sector 0. A disc left open gets its next session the same way, with the earlier files kept. Speed is taken from the drive's own list.
  • Checks: every direct burn is read back and compared (track list, CD-Text, codes, every audio sample or data sector). A laser-off test write is available, and every drive command is logged.
  • When it is used: on by default in the app for audio CDs (when the drive offers Session-at-Once) and dual-layer DVD-Video, and for a DVD-RW in the app and with burn-data / burn-iso (Windows' writer formats a DVD-RW for overwriting; a Settings switch or --windows-writer turns this off). Elsewhere it is off by default (--native on the command line) and IMAPIv2 writes, which is also the fallback.
  • Tested on real discs (one drive, LG GP60NB50): audio and data CDs on CD-R and CD-RW; mixed-mode CDs (data track, then audio) on a CD-RW and on CD-Rs (copied from CD-RW and CD-R, and burned on CD-R with write-offset correction on); data on DVD-R, DVD+R and DVD+RW; a DVD-RW closed in one pass, left open and given a second session, and in overwrite mode expanded and written over; a 60 s DVD-Video test disc on a DVD+RW, read back in full; a 6.5 GB dual-layer DVD+R with the layer break where it was asked for (SHA-256 equal to the image); a two-film DVD-9 played on an Xbox Series X across the layer change; three or four sessions added in turn on a CD-R, a CD-RW, a DVD-R and a DVD+R, every file read back identical.
  • Picture discs on a real drive (LG GP60NB50, disc-art burn --native): a CD-RW with the uncalibrated cd-80 geometry and a rim header showed only fine concentric stripes, the pattern of an angle drift (2026-11-18). A Verbatim DVD-R with a coarse calibration target was written in full, but the read-back check stopped at the first sector (picture sectors are not ordinary readable data) and the band edges in a photo could not be placed well enough to save a calibration (2026-11-21). On 2026-11-22 the same CD-RW was placed from a turn table measured by read timing (disc-art measure, --turn-map; both experimental): the first recognisable picture, three rings, twelve spokes and two words in place in a phone photo, with the spokes waved by about 2 degrees. Later CD-RW burns gave clock faces with sharp numerals and words, and a spoke pre-bent by 0.6 to 0.7 degrees per mm came out straight to 0.2 mm over 37 mm; an unbent spoke still leans by 1.6 to 3.4 mm, cause not found. The read-back check failed on picture sectors on the CD-RW each time, although every write was accepted. Three picture burns on blank CD-Rs of one batch were written in full and read back identical after careful re-reads (no photo recorded); discs of that batch come in two kinds of spiral that alternate on the spindle, so a turn table from the other kind winds the spokes up. A second DVD writer (Lite-On iHAS124) has burned one CD-R with direct drive commands (206 MB, 497 files, read back and every file identical, 2026-11-20); the same data through Windows' writer on a second CD-R took 338 s against 126 s. It was also probed read-only with a blank DVD-R, DVD+R, DVD-RW and CD-RW (2026-11-21): 16x, 12x, 8x and 6x on the DVD-R and DVD+R, 2x on the DVD-RW, 10x on the CD-RW, ready 10 to 18 s after loading. No DVD or audio disc has been written on it.
  • Simulator only so far: DVD-RAM (a real-disc test will not be done: the medium is out of production), dual-layer DVD-R, Blu-ray, CD-Extra (burning it, and copying an Enhanced CD whole) / Audio CD PAR2 recovery sessions, CD picture tracks added after a base .cue, a Mode 2 / XA data track in a mixed-mode CD, rip gap detection, the DVD-Video authoring options, the Blue Book layout for an Enhanced CD data session, every picture-disc option not in the burns above (disc-art: placing the picture with --scale and the offsets, the art band between two radii, the title ring, the rim header on calibrated CD, DVD and BD-R picture discs, the experimental audio CD picture in the pre-gap before track 1 and the Disc Art page, and the picture fill on data, DVD-Video and audio CD burns) and the Rosetta hybrid DVD-R with its rim header.
