## IgnisDisc v1.15

Free, open-source (GPL-3.0-or-later) CD/DVD burner, DVD-Video authoring tool, audio CD ripper and multi-disc archiver for Windows 10 and 11 (x64).

### Downloads and SHA-256 checksums
- **Installer** (`IgnisDisc-Setup.exe`, per-user, no admin rights): checksum added once the release build finishes
- **Portable** (`IgnisDisc-Portable-win-x64.zip`): checksum added once the release build finishes

Builds are not code-signed yet, so Windows SmartScreen may warn on first run.

### DVD-Video playback, dual-layer DVD-9 and subtitles
- **Navigation tables and title menus players accept**: rebuilt IFO and NAV packs to match `libdvdread`'s structures (`VMG` / `VTS` pointers, `VOBU` address and time maps, next/previous `VOBU` search links, and `VMGM CallSS` title chains), added 5-minute chapters, English subtitles rendered from `.srt` files, and a title menu (*Create title menu*, renamed from *Auto Play Menu*) with a still frame per film and *Play* / *Play with subtitles* buttons.
  - Checked with `libdvdnav` (`mpv`, `VLC`) and played on a real **Xbox Series X**: a film with menu, chapters and subtitles on a DVD+RW, and a two-film DVD-9 (103 + 86 minutes) burned to a Verbatim **DVD+R DL** with `burn-dvd --native`, where playback crossed the layer change on the second film's cell boundary without a stop.
- **Dual-layer DVD+R layer break control**: `burn-iso --native --layer-break <sectors>` and `burn-data --native --layer-break <sectors>` set the layer break before writing (verified on a real Verbatim DVD+R DL with the 6.5 GB Ubuntu 26.04 ISO; disc SHA-256 matched the image).
- **Per-movie subtitle controls on the DVD-Video screen**: each added film now shows its subtitle status (an `.srt` found beside it with cue count, a picked `.srt`, generated subtitles, none, or unreadable) with **Choose .srt...** and **No subtitles** buttons.
- **Generated subtitles (optional 1-click download, nothing bundled)**: *Install subtitle tool (1-Click)* / `install-subtitle-tool` downloads `whisper.cpp` 1.9.5 and speech models (pinned by SHA-256 into `%LOCALAPPDATA%\Programs\whisper.cpp`) — CUDA + `large-v3-turbo` (2.3 GB) on NVIDIA GPUs with driver 551.61+, or the processor build + `base` (160 MB) elsewhere. `generate-subtitles` and `burn-dvd --generate-subtitles` (and the *Generate subtitles* checkbox in the app) generate `.srt` tracks for films that have none, cached in `%LOCALAPPDATA%\IgnisDisc\SubtitleCache`. Authored end to end on a PC from a 5-minute excerpt (subtitles and *Play with subtitles* menu button work); not yet burned and played in a stand-alone player.
- **Authoring reliability**: FFmpeg processes that produce no output for 3 minutes are stopped instead of hanging indefinitely; subtitle muxing failures fall back to authoring without that subtitle track and warn; real FFmpeg encoding failures fail with an error rather than burning placeholder test video; and IgnisDisc now prefers its own 1-click FFmpeg install over an older `ffmpeg` on `PATH` (muxing DVD subtitles requires a recent FFmpeg build; a 2021 build crashed).

### Desktop app defaults, notices and settings
- **Direct drive commands on by default for Audio CDs and dual-layer DVD-Video**: the Audio CD screen now starts with *Direct drive commands* turned on so CD-Text, ISRC/catalog codes and exact gaps are written by default; if a drive does not report Session-at-Once, the app burns with the Windows writer instead and notes why (explicitly checking the box yourself still refuses unsupported drives). The DVD-Video screen turns direct drive commands on automatically whenever the added movies require a dual-layer disc, and off again for single-layer discs until you toggle the box yourself. Data discs, single-layer DVDs and the CLI continue to use the Windows writer unless direct drive commands / `--native` are selected.
- **Burn-finished notice and eject by default**: finished and failed burns across every workspace now play the Windows notification sound, flash the taskbar button when the window is in the background, and show the result dialog (controlled by *Tell me when a burn finishes* in Settings, on by default). *Eject after burn* is now on by default (older settings files migrate automatically).
- **Instant settings save**: changing any setting in Settings saves immediately (the Save button has been removed; *Reset* writes defaults back to `settings.json`).

### Audio CD recovery session, loudness, inputs and picture tracks
- **Audio CD PAR2 recovery session & ripper repair (experimental, simulator-tested)**: Session-at-Once `--native` audio burns can leave session 1 open (`--recovery-session` or the option on the Audio CD screen, off by default) and append an Enhanced CD (CD-Extra) ISO 9660/Joliet data session holding PAR2 recovery volumes and track checksums. `rip-audio --repair` (and the Audio CD ripper option) uses session 2 to verify and rebuild damaged samples. Tested in the built-in drive simulator with `par2`, not yet run on a real disc or car CD player.
- **-18 LUFS loudness normalisation and Opus / Ogg / MP3 gapless decoding**: Audio CD burns now support BS.1770-4 gated loudness normalisation to `-18 LUFS` (per track or per album) with a 4x-oversampled `-1 dBTP` true-peak limiter (`--loudness track|album|off` on `burn-audio` / `audio-plan`, and checkboxes on the Audio CD screen). `.opus` files are accepted, and Opus, Ogg Vorbis and MP3 files decode through the optional FFmpeg download with exact sample-length trimming (RFC 7845 / LAME / Xing headers) for gapless albums. Tested on files and the virtual drive (not yet on a burned disc); the built-in FLAC decoder is also checked against files produced by the official `flac` 1.5.0 encoder.
- **Rip cover art and tags**: the Audio CD ripper screen adds a cover-image picker (matching `rip-audio --cover`, rejecting images too large for a FLAC picture block before reading the disc) and includes ReplayGain 2.0 tags in ripped FLAC files just as the CLI does.
- **CD picture tracks (`.cue` pipeline, simulator-tested)**: ports `DiscImageStudio`'s CD picture-track generator, CIRC interleaver and read-back decoder, and appends generated picture WAVs as the last audio track of a `.cue` sheet. Verified against upstream SHA-256 golden outputs and burned/read back on the virtual drive; no standalone CLI command or real-disc burn yet.

### Multi-disc archives, DiscJuggler `.cdi` and 37-command CLI parity
- **3-zone archive recovery layout**: `archive-stage` now splits each disc's PAR2 recovery volume into three packet-aligned parts placed in inner, middle and outer zones of the disc, each preceded by a copy of the ISO 9660 Primary Volume Descriptor whose locations are recorded in the Application Use field. `recover` reads from those descriptor copies and scans UDF self-locating tags when sector 16 or the UDF anchors are destroyed. Tested on disc images with real `par2`, destroying sector 16, UDF anchors and entire zones; not yet run on a real scratched disc.
- **1-click `par2cmdline-turbo` 1.5.0**: *Install par2 (1-Click)* / `install-par2` now installs `par2cmdline-turbo` 1.5.0 (verified against pinned SHA-256 hashes; ~7–11x faster than `par2cmdline` 1.4.0 on DVD/BD-sized archives in local measurements) and detects installed `par2cmdline` 1.4.0 installs in Archive and Settings to offer an update.
- **Archive health certificates**: `archive-burn --health-certificate` (off by default) writes `discNN.HEALTH.json` and `discNN.HEALTH.svg` alongside the staged disc folder (drive, media ID, speed curve, verify status, and per-minute CD C2 health counts), and `check-disc --compare <file>` compares a later read against it (tested on the virtual drive and tests only).
- **DiscJuggler `.cdi` image reading**: `image-info`, `convert-image`, `burn-iso` and `verify --iso` read `.cdi` v2, v3 and v3.5 images (tested on synthetic files built from the published format, not yet on images written by DiscJuggler).
- **CLI parity (37 commands)**: added `image-info`, `convert-image`, `author-dvd`, `jewel-cover`, `audio-plan`, `burn-queue`, `book-type`, `repair-par2`, `settings`, `tools`, `install-ffmpeg`, `install-par2`, `check-update`, `eject` and `load`, plus `--tracks-file`, `--plan-only`, `--normalize`, `--rms-level`, `--loudness`, `--crossfade`, `--pregap`, `--songwriter`, `--upc`, `--no-cd-text`, `--append`, `--no-burnfree` and `--post-action` (requiring `--confirm-shutdown` for shutdown).

### Fixed
- **Blank discs read right after loading**: a blank recordable disc queried within the first ~1.7–3.2 s after closing the tray (when IMAPIv2 is not ready yet and `READ CAPACITY` reports 1 sector) now reports as loading rather than a finished 1-sector disc; burns and erases wait up to 20 s for the drive to settle instead of refusing immediately.
- **Dual-layer calibration timeout**: raised the first `WRITE` SCSI command timeout from 60 s to 4 minutes so drives calibrating on a dual-layer DVD+R (measured at 61–85 s on an LG GP60NB50) do not fail before recording starts.
- **Status text & layout**: late progress callbacks no longer overwrite a finished burn's status line; Audio CD option checkboxes wrap onto their own row so *Direct drive commands* is not clipped on the right; plain radio buttons (*Gapless DAO* / *TAO*) follow the active theme text colour in Dark Mode; and the DVD-Video progress bar and status text keep full width.

### Known limitations
- Builds are unsigned, so Windows SmartScreen warns on first launch.
- Direct drive commands have run on real hardware on one drive model only (LG GP60NB50). DVD-RW, DVD-RAM, dual-layer DVD-R, Blu-ray, CD-Extra / Audio CD PAR2 recovery sessions, CD picture tracks, archive `HEALTH.json` certificates, and `eject` / `load` have run only in the built-in drive simulator or against image files, not on real discs.
- Stand-alone player playback has been tested on an Xbox Series X for DVD-Video (single-layer DVD+RW and dual-layer DVD+R); no audio CD from this release has been checked in a stand-alone CD player, and no disc authored with machine-generated subtitles has been burned and played in a stand-alone player yet.
- DiscJuggler `.cdi` support was checked only on hand-built files following the published format, not on images created by DiscJuggler.
- On slim USB drives with spring-latched trays, a laser-off `--test-first` run still stops after the test write so the user can push the tray open and shut by hand; after appending a session to a DVD-R, Windows may require reinserting the disc to show the new files; open multi-session discs keep Joliet-only file names up to 64 characters; and the weak-media speed cap applies in the app but not yet in the CLI.
