## IgnisDisc v1.16

Free, open-source (GPL-3.0-or-later) CD/DVD burner, DVD-Video authoring tool, audio CD ripper and multi-disc archiver for Windows 10 and 11 (x64).

### Downloads and SHA-256 checksums
- **Installer** (`IgnisDisc-Setup.exe`, 83.5 MB, per-user, no admin rights): `5A8AB5D1D5C865C410225464D945C433091A5025DDDB337F5C43FA2F7E55ECDD`
- **Portable** (`IgnisDisc-Portable-win-x64.zip`, 82.9 MB): `0CF11B392D2EBA16823CA5B07E420E711E0B448C91597028B1C8B5B1152D01C1`

Builds are not code-signed yet, so Windows SmartScreen may warn on first run.

### DVD-RW: sessions you can add to, checked on a real disc
Run on one drive (LG GP60NB50) with a Ritek DVD-RW, every file of every burn compared by SHA-256 through Windows and in a rip of the disc.
- **Direct drive commands are now the default for DVD-RW.** Windows' own writer formats every blank DVD-RW for overwriting before it writes, even when you ask to leave the disc open, so it can never hold a second session. IgnisDisc's direct writer keeps it sequential. The Data Disc, Disc Image, Archive and DVD-Video screens tick *Direct drive commands* by themselves while a DVD-RW is in the drive and untick it for other discs; a tick you set yourself always stays. Settings has *Use direct drive commands for DVD-RW* (on) to turn this off. On the command line `burn-data` and `burn-iso` use the direct writer for a DVD-RW and say so; `--windows-writer` keeps Windows' writer for that command.
- **Adding a session to a DVD-RW.** A DVD-RW left open gets its next session, with the earlier files kept. On the real disc the second session started 28,688 sectors after the first (as on DVD-R) and closed the disc; all 13 files of both sessions read back identical. Windows showed the new session after the disc was taken out and put back in. Windows reports an open DVD-RW as a disc to write over, so the direct writer now asks the drive itself; Windows' writer still refuses that disc without leave to replace its files, because it would write it over.
- **The burn dialog follows the writer**: with direct drive commands on, an open DVD-RW reads *Appendable* instead of *Burning will REPLACE everything*.
- **A DVD-RW in overwrite mode**: the direct writer expanded a disc that Windows had formatted only partly (65,264 sectors) and wrote 230 MB over it; every file identical.
- **When a DVD-RW cannot be left open**: after a quick erase the drive only writes a DVD-RW in one pass. Leaving it open needs a full erase (*Full Erase* in Drive Utilities, or `erase --full`; about 30 minutes at 2x). A burn asked to leave such a disc open now goes to Windows' writer with the reason instead of failing.
- **A warning when a disc could not stay open**: if Windows' writer formats a DVD-RW for overwriting on a burn that was to leave it open, the result now says so.

### DVD-Video
- **Disc size from running time, not file size**: the DVD-Video screen reads each movie's running time in the background and plans with the bitrate the authoring will use. It shows whether the movies fit at full quality, will be compressed (with the bitrate and a plain quality word), need a dual-layer DVD, or are too long for any DVD (then *Burn* and *Build ISO* are off). A 15 GB 4K film no longer looks as if it needs a dual-layer disc. A burn is refused before converting when the disc in the drive is too small.
- **Dual-layer offered when it keeps the picture clearly sharper**: when a 4.7 GB DVD would have to compress the movies and a dual-layer DVD keeps at least 15% more bitrate, both are shown as a choice (for example a 2 h 20 min film: 3,587 kbps, good quality, or 6,000 kbps, full quality).
- **More authoring choices** on the DVD-Video screen and in `author-dvd` / `burn-dvd`: title menu on or off, menu autoplay countdown, what happens after a title (next title or back to the menu), chapter interval or none, subtitles shown by default or not, subtitle size, a fixed video bitrate or fit-to-disc, and editable menu names per title. Checked with tests of the written IFO, NAV and subtitle bytes; not yet played on a stand-alone player.
- **New DVD** clears the movies, subtitle choices, disc name and menu title for the next disc.

### Audio CD ripping
- **Gaps, hidden track-one audio and pre-emphasis are detected when ripping**: the ripper finds each track's INDEX 00 from the disc's sub-channel, tells hidden audio before track 1 from silence, and writes FLAGS (pre-emphasis, copy permitted), CATALOG and ISRC into the ripped `.cue`, so a burn from that `.cue` keeps them. Tested against the built-in drive simulator; not yet on a pressed CD.

### Experimental
- **`rosetta ladder`** (command line only) writes a DVD-R image whose data forms a visible resolution ladder on the disc's surface: labelled rungs at the inner, middle and outer radius, with a JSON file giving each rung's position. The image has not been burned and looked at on a real disc yet. The picture-encoding library behind it (DVD data frames, EFMPlus, ECC, read-back rendering) is ported from DiscImageStudio and reproduces its reference outputs byte for byte; no screen uses it yet.

### Fixed
- The direct writer waited at most 10 minutes for a drive to finish writing the lead-out; closing a small Disc-At-Once DVD-RW took the test drive 376 s, so a slower disc could have been reported as failed while the drive was still closing it. The limit is now 20 minutes.
- Checking the version of a `par2.exe` that is not a Windows program (for example a text file) no longer makes Windows show an *Unsupported 16-Bit Application* window.
- The DVD-Video planner no longer fails on more than 8.5 GB of input movies.

### Known limitations
- Builds are unsigned, so Windows SmartScreen warns on first launch.
- Direct drive commands have run on real hardware on one drive model only (LG GP60NB50). DVD-RAM, dual-layer DVD-R, Blu-ray, CD-Extra / Audio CD PAR2 recovery sessions, CD picture tracks, archive `HEALTH.json` certificates, `eject` / `load`, gap detection when ripping, and `rosetta ladder` images have run only in the built-in drive simulator or against image files, not on real discs.
- Leaving a DVD-RW open needs a full erase first (about 30 minutes on a 2x disc); after adding a session to a DVD-RW or DVD-R, Windows may need the disc reinserted to show the new files; open multi-session discs keep Joliet file names of up to 64 characters.
- Stand-alone player playback has been tested on an Xbox Series X for DVD-Video discs from v1.15; the new DVD-Video authoring choices, and discs with machine-generated subtitles, have not been played on a stand-alone player yet. No audio CD from this release has been checked in a stand-alone CD player.
- DiscJuggler `.cdi` support was checked only on hand-built files following the published format, not on images created by DiscJuggler.
- On slim USB drives with spring-latched trays, a laser-off `--test-first` run still stops after the test write so the user can open and close the tray by hand, and the weak-media speed cap applies in the app but not yet in the command line.
